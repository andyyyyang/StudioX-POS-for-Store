# 架構

## 一句話

**每個動作都是一筆不可改的事件；狀態是事件重播出來的。** iPad 是主角（斷網照常營業），後台是另一個會收、會轉的節點。

```
            ┌──────────── StudioX Console（console.studiox.tw）────────────┐
            │  配對碼查店家 /api/pos/resolve                                    │
            │  服務插件開通「門市 POS」「電子發票」、方案（幾台收銀機）           │
            │  /api/app/me 的 sites[].pos（App 首頁的門市營收）                  │
            └──────────────▲───────────────────────────▲───────────────────┘
                           │ 簽章的 relay（site-pos）    │ MCP：pos_report、pos_sale…
            ┌──────────────┴───────────────────────────┴───────────────────┐
            │  店家的後台（atelier-cms，pos 模組）                               │
            │  pos_events（全部事件）→ 投影：pos_sales／lines／payments、       │
            │  pos_invoices（48 小時內上傳財政部）、pos_shifts、會員累積消費、庫存 │
            │  菜單、桌位、人員（PIN）、裝置、字軌、訂位                          │
            └──────────────▲───────────────────────────────────────────────┘
                           │ /api/pos/v1：bootstrap、events（推／拉）、invoice/rolls…
     ┌─────────────────────┴──────┐        同一個 Wi-Fi：Bonjour＋AES-GCM
     │ iPad 櫃台（收銀機）          │ ◀───────────────────────────────▶ iPad 手持（點餐機）、廚房螢幕
     │ 事件日誌（fsync）→ StoreState │
     └─────────────────────────────┘
```

## 事件（POSCore/Events.swift）

- 25 種事件：開單、加品項、改數量／價格／折扣、作廢、送單、出餐進度、換桌、併桌、拆單、印結帳單、收款、退回付款、
  開發票、作廢發票、結帳、作廢單、退款、清桌、開班、錢櫃進出、交班、打卡、賣完。
- 每筆有 `id`（去重）、`deviceId`＋`seq`（這台的流水號，不跳號）、`lamport`（順序）、`prevHash`→`hash`（雜湊鏈）。
  後台照 `SHA-256(id|deviceId|seq|lamport|at|staffId|type|prevHash|data)` 驗：**少一筆、改過一筆都看得出來**（防止刪單）。
- 重播順序：`(lamport, deviceId, seq)`。收到別台的事件就把自己的 Lamport 時鐘調到比它大：「看到才做」的事一定排在後面。
- `StoreState.apply` 只看事件內容（不看現在時間、不碰網路與檔案）：**每台 iPad、後台、測試算出來一模一樣**。
- 斷線時兩台都動了同一張單：加品項各自保留；兩台都結帳 → 第二次結帳被擋下、兩筆錢都記著、留一筆衝突給店長（畫面上方紅條）。

## 金額（POSCore/Pricing.swift）

整數「分」存、整數「元」算（新台幣）。

```
品項小計 = Σ (單價＋加料) × 數量            （作廢的不算）
小計     = 品項小計 − 單品折扣
整單折扣 = 小計 × %（或固定金額）→ 最大餘數法分攤到每一行（報表的品項營收、發票的品項金額都對得起來）
服務費   = (小計 − 整單折扣) × 服務費率      （只有內用）
總計     = 小計 − 整單折扣 + 服務費          ← 發票金額（含 5% 營業稅）
應收     = 總計 + 小費                      ← 小費不開發票
```

結帳那一刻 iPad 算好整份 `SaleRecord` 放在 `ticket.closed` 事件裡；後台存那一份、只檢查加起來對不對（金額算法只有一份）。

## 電子發票（POSInvoice）

- **號碼段**：後台把財政部配的字軌切成一段一段（預設 50 張）給每台 iPad（`POST /invoice/rolls`）。每台只用自己的段：
  好幾台同時開、斷網開，都不會撞號。剩不到 10 張、或下一期最後 3 天就自動再要。
- **用過哪些號碼**從事件算（`StoreState.invoices`），不另外存：日誌是唯一的真相。
- **開立順序**：算好發票 → `invoice.issued`＋`ticket.closed` 一起寫進日誌（fsync）→ 才印證明聯。當機也不會「印了卻沒記」。
- **金額**：B2C 銷售額＝含稅總計、稅額 0；B2B（統編）銷售額＝round(總計 ÷ 1.05)、稅額＝總計 − 銷售額。
  品項照原價列，折扣、服務費各一行，加起來剛好等於總計。
- **證明聯**：一維條碼 Code 39 = 期別 5 碼＋號碼 10 碼＋隨機碼 4 碼；左 QR = 號碼、民國日期、隨機碼、銷售額與總計（16 進位）、
  買方與賣方統編、AES-128-CBC 加密驗證碼（24 碼）、`:**********:`品目筆數…；右 QR = `**`＋放不下的品目。
  每個 QR Code 不超過 200 bytes（5.7 公分寬也掃得到），放不下的品目照實寫筆數。
- **退款**：同一期整張退 → 作廢；部分退款、跨期 → 折讓單（印「營業人銷貨退回、進貨退出或折讓證明單」給客人簽）。
- **上傳**：後台的佇列在 48 小時內上傳（F0401 開立、F0501 作廢、G0401 折讓、期末 E0402 空白未使用字軌），36 小時還沒上傳就警示。

> 上線前請用財政部的「電子發票 QR Code 驗證」與加值中心的測試環境驗一次證明聯與上傳格式。

## 同步（POSSync）

| | |
|---|---|
| 本機 | `own.jsonl`（這台的事件，寫入就 fsync）、`remote.jsonl`（別台的，驗過雜湊才收）、`cursor.json`（送到哪、拉到哪）。最後一行寫到一半（當機）開機時修掉。每天把 7 天前、已送出、不屬於開著的單與班的事件移到 archive/ |
| 雲端 | 一批 200 筆照流水號送；後台說 `chain_gap` 就從它要的那筆重送；`bad_hash` 隔離交給人處理。拉：從 `serverSeq` 接著拿。失敗 2、4、8…最多 60 秒重試；記了新事件、心跳說後台有新的就馬上跑 |
| 區網 | Bonjour `_studiox-pos._tcp`；連上先交換「每台看到第幾筆」互相補齊，之後記了就送。訊息先 HMAC 簽章（5 分鐘內）再 AES-GCM 加密，金鑰是店家的 mesh key（bootstrap 給已配對的裝置） |

從雲端、從區網來的同一筆事件只會記一次（用 id 去重）。

## 右側固定鍵盤

`KeypadController` 是唯一的數字輸入：`await keypad.ask(spec)` 把鍵盤換成那個題目（`KeypadSpec`：數量、金額、PIN、統編、電話、
愛心碼、代碼、張數），打完按確認才回傳；`validate` 不過（PIN 不對、超過可退金額）就留在鍵盤上、紅字搖一下。
沒人要數字時，打的數字是「數量」（點品項時拿走）或「品號」。外接鍵盤、條碼掃描器打的數字也進同一個鍵盤。

規則（POSCore/Keypad.swift）有測試；畫面（StudioXPOS/Keypad/KeypadDock.swift）照規則畫。

## 後台（atelier-cms 的 pos 模組）

- 模組 `pos`（`CMS_MODULES` 加 `pos`）：`/admin/pos/*`、`/api/pos/v1/*`；接 StudioX 的網站由 console 開通服務 `pos` 與 `einvoice`
- 方案的 `pos.registers`：最多幾台收銀機
- 投影：`ticket.closed` → 銷售（含會員累積消費、網路商店庫存）；`invoice.*` → 發票上傳佇列；`shift.closed` → 交班單、推播給負責人
- 報表：後台儀表板、營運報表（ops_report）多了門市；MCP 工具 `pos_report`、實體 `pos_sale`、`pos_item`、`pos_reservation`
  （StudioX App、Claude 這類 AI 都看得到）
