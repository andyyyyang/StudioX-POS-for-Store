# 設計規則

StudioX POS 的畫面一律照這幾條。新增或修改畫面前先看一遍；截圖在 `docs/screenshots/`（提交訊息帶 `[screenshots]` 會重拍）。

## 按鈕與動作：一個地方只有一個最明顯的動作

收銀台是站著、手忙的時候用的：眼睛一掃就要知道「下一步按哪裡」。按鈕越多，越要停下來找。

1. **一個區域一個主要動作**（實心，`ActionBar` 的 `primary`）。整個畫面的品牌橘（`accent`）最多一個：結帳、確認、入場、交班這種「做完這件事」的動作。
2. **常用的次要動作最多兩個**（細框）。其他收進「⋯」（`MoreMenu`）。直接用 `StudioXPOS/Components/ActionBar.swift` 的 `ActionBar`：多給的次要動作會自動收進「⋯」。
3. **清單與卡片不放按鈕列。** 整張卡片可以點，點了選起來；選起來的那一筆，動作出現在**同一個固定的地方**：
   - 有圖的畫面（桌位圖、預約表）：卡片旁邊的浮動面板
   - 清單（訂位、候位、訂單、會員、報到）：右邊的明細面板，或清單下方固定的動作列
   - 一張卡片最多一個「一按就完成」的快捷（候位的「入座」、廚房的「好了」、報到的「入場」），而且只在最常用的那個狀態出現；其他的選起來才出現
4. **頁首右上最多一個主要按鈕。** 同一類的新增合成一個：「＋ 新增」點了選訂位或候位，不要兩個按鈕並排。
5. **切換用分段控制**（今天／這一班、進行中／全部、樓層），不要一排各自獨立的按鈕。
6. **危險的動作不放在主要位置**：作廢、退款、取消、刪除放在「⋯」裡，紅字（`destructive`），按了要確認或主管授權。
7. **同一個動作在同一個畫面只出現一次。**
8. **狀態用顏色與標籤表示，不是用按鈕。** 「已到」「服務中」是狀態；改狀態的動作放在選起來後的面板。
9. **字不能被截斷。** 寬度不夠時減少一行裡的東西、換成兩行、或把次要資訊收起來；名字、金額、時間永遠完整。
10. **要打數字的一律用右側鍵盤**，不要用會蓋住鍵盤的 sheet；面板都放在工作區裡。

## 每一頁的骨架

```
┌ 頁首：標題（英文大字＋中文小字）·········· 一個主要按鈕 ┐
│ 篩選／切換（分段控制）                                  │
│ 內容：清單或圖（點了選起來）                            │
│ 選起來的那一筆：動作在固定位置（面板或下方動作列）       │
└────────────────────────────────────────────────────────┘
```

## 文字

- 數字用等寬數字（`.monospacedDigit()`）；金額 `MoneyText`
- 一行放不下時：先拿掉次要資訊，再縮小字（`minimumScaleFactor` 不低於 0.7），最後才換行
